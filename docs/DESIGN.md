# 디자인 규칙 — 오늘공고

목업(`mockup/오늘공고.dc.html`)이 쓰는 **Broadsheet** 디자인 시스템을 이 프로젝트에 옮기는 규칙이다.
원본은 `mockup/_ds/broadsheet-01d703a1-1331-4b61-a14b-b744189e8823/` — `readme.md`(지침)와 `styles.css`(토큰)가 원전이다.

**이 문서의 목적은 하나다: 화면을 여러 번에 나눠 고쳐도 같은 결과가 나오게 하는 것.**
색·크기·여백을 고를 일이 생기면 여기서 찾고, 여기에 없으면 여기에 먼저 적고 나서 코드를 고친다.

## §1 원칙

Broadsheet은 **웹에 올린 신문 조판**이다. 종이색 바탕에 먹빛 세리프, 공정 잉크(시안·마젠타)를 스팟 컬러처럼 아주 조금.

1. **박스와 선으로 구조를 만들지 않는다.** 위계는 글자 크기와 여백이 만든다.
2. ~~**전부 세리프다.** UI 크롬에 산세리프를 섞지 않는다.~~ → **폐기 (D9).** 산세리프로 갈아탔다.
3. **시안이 상호작용, 마젠타는 더 드문 두 번째 스팟.** 한 작은 컴포넌트에 두 잉크를 같이 쓰지 않는다.
4. **왼쪽 정렬, 비대칭.** 내용은 왼쪽에 붙고 오른쪽에 여백이 남는다. — **예외는 목록 화면의 히어로 한 블록뿐이다** (D8).
5. **여백 스케일을 좁히지 않는다.** 밀도 1.25배가 이미 토큰에 박혀 있다.

> **원칙 2는 두 번 판정했다.** 2026-08-06 조판 개편에서 처음에는 세리프를 지켰다 — 비교에 쓴
> 목업이 웹폰트 CSP에 막혀 세리프를 시스템 바탕체로 렌더했으니, 그 비교로 서체를 버리는 것은
> 근거가 서지 않았기 때문이다. **그 다음 사용자가 배포된 실제 화면을 보고 산세리프를 요청했다.**
> 실제 서체로 본 판단이므로 그것으로 뒤집었다 (§7). 목업의 한계가 아니라 판단의 근거가 바뀐 것이다.

### 이 프로젝트에서 지금 어긋나 있는 것

현재 코드가 원칙을 어기는 지점이다. 고칠 목록이기도 하다.

| 어긋난 곳 | 지금 | 고칠 방향 |
|---|---|---|
| 목록 카드 구분 | `border-b`로 행을 나눔 ([PolicyCard.tsx:33](../src/components/PolicyCard.tsx:33)) | `.card` + 여백 간격 (원칙 1) |
| 상세 화면 블록 | 섹션마다 `rounded border` 박스 | 판정 블록만 `.card`, 나머지는 여백 (원칙 1) |
| 서체 | `Arial, Helvetica, sans-serif` ([globals.css:25](../src/app/globals.css:25)) | 서체 페어링 — 세리프로 갔다가 D9로 산세리프로 돌아왔다. **기본 스택으로 두지 않는다는 것이 요점이었다** |
| 배지 색 | `emerald`·`sky`·`green`·`teal`·`amber`·`slate` 6계열 | 시안·마젠타·중성 3계열 (원칙 3) |
| 관리자 막대 | Tailwind 기본 `gray-*` | 토큰 상속만 (범위 밖, §5.4) |

### Broadsheet에서 의도적으로 벗어나는 것

**일탈은 아래 열 개뿐이다.** 여기 없는 일탈이 코드에 있으면 그건 버그다.

D6~D10은 2026-08-06 조판 개편에서 들어왔다. 다섯 다 원본이 아니라 **레퍼런스 사이트**(bnbicons.com)의 구성을 옮기며 생긴 것이고, 근거는 §7에 있다.

## §2 토큰

### §2.1 색 ✅

역할 토큰만 쓴다. 램프 값을 컴포넌트에 직접 박지 않는다.

| 역할 | 라이트 | 다크 | 쓰는 곳 |
|---|---|---|---|
| `bg` | `#f3f2f2` 종이 | `#201e1d` 먹 | 페이지 바탕 |
| `surface` | `#fbfafa` | `#2d2b2b` (neutral-900) | 카드·타일·입력칸·외곽선 버튼 채움 |
| `text` | `#201e1d` | `#f3f2f2` | 본문 |
| `text-muted` | text 70% | text 70% | 힌트·메타·보조 설명 (§6.1) |
| `text-faint` | text 55% | text 55% | 장식용 캡션. **읽어야 하는 정보에 쓰지 않는다** |
| `accent` | `#0088b0` 시안 | `#99e0ff` (accent-300) | 링크·아이콘·큰 글자·테두리 |
| `accent-ink` | `#006786` (accent-700) | `#99e0ff` (accent-300) | **채움 배경**의 잉크 (D4) |
| `accent-2` | `#d6006c` 마젠타 | `#ffc0d0` (accent-2-300) | 두 번째 스팟 |
| `divider` | text 16% | text 16% | 꼭 필요한 한 줄. 기본은 여백 |

**다크는 종이와 먹을 뒤집은 것이다.** 먹이 바탕이 되고 종이가 글자가 된다 — "잉크 위에 인쇄한 종이".

**카드는 언제나 바탕보다 밝다** (D7). 라이트에서 `surface`(#fbfafa)가 종이(#f3f2f2)보다 밝고, 다크에서도 `#2d2b2b`가 먹(#201e1d)보다 밝다 — 두 모드에서 층의 방향이 같다. 따라오는 규칙 둘:

- **카드 안에서 한 겹 더 들어가는 자리는 `bg`(종이색)다.** 이제 종이색이 아래 층이다. 목록 카드의 '확인이 필요한 것' 패널, 타일의 머리띠가 여기 해당한다. 층 대비는 1.07:1 — 눈에 겨우 잡히는 정도이고, 실제 경계는 `divider` 한 줄이 만든다.
- **`.input`과 `.btn-secondary`도 `surface`다.** 종이 위에서 흰 칸으로 도드라진다. 투명하게 두면 흰 카드 위에서 사라진다.

램프는 원본 `styles.css`의 값을 그대로 가져온다 (neutral / accent / accent-2 × 100~900). 사용 규칙:

| | 라이트 | 다크 |
|---|---|---|
| 옅은 채움·호버 | 100~300 | 800~900 |
| 기준 | 500 | 300~400 |
| 채움 위 글자·눌림 | 700~900 | 100~300 |

`--color-process-yellow`(#edbb00)는 **인쇄 처리 전용**이다. 본문·크롬·배지에 쓰지 않는다.

### §2.2 그림자 ✅

| | 라이트 | 다크 |
|---|---|---|
| `sm` | `0 1px 2px` 먹 14% | 헤어라인 테두리 + `0 1px 2px` 검정 40% |
| `md` | `0 3px 10px` 먹 16% | 헤어라인 + `0 3px 10px` 검정 45% |
| `lg` | `0 12px 32px` 먹 22% | 헤어라인 + `0 12px 32px` 검정 55% |

다크에서 그림자는 어둠으로 안 보인다. 원본 주석이 말하는 대로 **헤어라인 테두리 + 주변 어둠**으로 바꾼다.

### §2.3 타이포 ✅

```
--sans: "Source Sans 3", "Noto Sans KR", system-ui, sans-serif   (본문 400 / 제목 700)
```

**산세리프다** (D9). 원본과 다른 유일한 큰 결정이고, 근거는 §7에 있다. 서체만 갈아탔고 **페어링 구조는 그대로다** — Source Sans 3은 전에 쓴 Source Serif 4의 산세리프 형제라 자폭과 리듬이 같은 계열이다.

**Source Sans 3을 앞에 둔다.** 라틴·숫자는 Source Sans 3이 잡고, 한글은 글리프가 없으므로 Noto Sans KR로 넘어간다. 순서를 바꾸면 숫자까지 Noto가 가져간다. D2가 말하는 페어링 이유는 서체가 바뀌어도 그대로다.

스케일 — 실제로 쓰는 단계만 고정한다. **여기 없는 크기를 쓰지 않는다.**

| 이름 | 크기 | 행간 | 용도 |
|---|---|---|---|
| `hero` | **44px / 700** | 1.08 | 목록 화면 히어로 **한 자리뿐** (D10). 자간 -0.03em |
| `display` | 32px / 700 | 1.12 | 첫 방문 안내 제목. 좁은 화면에서 `hero`가 내려앉는 자리 |
| `title` | 25px / 700 | 1.16 | 화면 제목 (상세 h1, 목록의 '공고 둘러보기') |
| `section` | 20px / 700 | 1.2 | 마스트헤드 브랜드, 섹션 제목 |
| `sub` | 16px / 700 | 1.2 | 소제목 (h3). 히어로 부제는 여기에 `font-normal`을 얹는다 |
| `body` | 15px / 400 | **1.7** | 본문 |
| `compact` | 14px / 400 | 1.55 | 카드 안 짧은 글, 버튼·입력칸 |
| `small` | 13px / 400 | 1.6 | 보조 설명·힌트 |
| `micro` | **12px** / 400 | 1.4 | 배지·메타·키커. **이보다 작게 쓰지 않는다** |

**제목 굵기는 전부 700이다** (전에는 600). 세리프는 획 대비가 굵기 일부를 대신해 주지만 산세리프는 굵기밖에 없어서, 600은 제목으로 안 읽힌다. 히어로 안의 강조 구절만 800이다.

**히어로는 `text-display sm:text-hero`로 쓴다.** 375px에서 44px은 세 줄로 넘친다. `clamp`를 쓰지 않은 것은 두 값이 다 스케일 위에 있어야 하기 때문이다 — 중간값이 생기면 "여기 없는 크기를 쓰지 않는다"가 무의미해진다.

**D2 보정 세 가지:** (서체가 바뀌어도 셋 다 유효하다)
- 본문 행간을 1.55 → **1.7**. 한글은 글자마다 밀도가 높아 원본 행간에서 뭉친다.
- 최소 크기를 10~11px → **12px**. 원본 `.card-kicker`(10px)·`.tag`(11px)·`figcaption`(11px)이 전부 12px로 올라간다.
- 키커는 `text-transform: uppercase`를 걸지 않는다 — 한글에 효과가 없다. `letter-spacing: 0.08em`만 남긴다.

숫자는 배지·통계에서 `tabular-nums`. **이탤릭은 쓰지 않는다** — 강조할 구절이 대부분 한글이고 한글 산세리프에 이탤릭 페이스가 없어 합성 기울임이 된다. 이탤릭 페이스를 아예 싣지 않았다. 강조는 굵기다.

### §2.4 여백 ✅

**Tailwind의 `--spacing`을 `5px`로 놓으면 Broadsheet 스케일과 정확히 일치한다.**

Tailwind 기본값은 `0.25rem`(4px)이고 Broadsheet은 5·10·15·20·30·40 — 5px × n이다. 원본이 말하는 "density 1.25×"가 곧 `4px × 1.25 = 5px`이다.

| Broadsheet | 값 | Tailwind |
|---|---|---|
| `--space-1` | 5px | `p-1` `gap-1` `mt-1` |
| `--space-2` | 10px | `-2` |
| `--space-3` | 15px | `-3` |
| `--space-4` | 20px | `-4` |
| `--space-6` | 30px | `-6` |
| `--space-8` | 40px | `-8` |

> ⚠️ 이 한 줄이 **기존 코드의 모든 여백 유틸리티를 1.25배로 늘린다.** 의도한 결과다. 다만 `w-44`·`h-*` 같은 **고정 크기 유틸리티도 같은 스케일을 타므로** 폼 입력칸 폭은 구현 때 다시 본다 (§8).

컨테이너 폭 — 목업을 따른다. 토큰으로 내려 `max-w-page` / `max-w-read`로 쓴다.

| 화면 | 폭 | 유틸리티 |
|---|---|---|
| 목록 (`/`) · 헤더 | 1040px | `max-w-page` |
| 상세 (`/policies/[id]`) | 680px | `max-w-read` |
| 프로필 (`/profile`) | 680px | `max-w-read` |

### §2.5 반경 ✅ (D6)

| 이름 | 값 | 쓰는 곳 |
|---|---|---|
| `xs` | 2px | 인용 하이라이트(`<mark>`)처럼 글자에 붙는 것 |
| `sm` | 8px | 버튼 · 입력칸 · 카드 **안**의 패널 |
| `md` | 14px | 카드 · 타일 |
| `lg` | 18px | 내 조건 카드처럼 한 단 큰 상자 |
| `pill` | 999px | 태그 · 칩 · 보기 전환 |

여백과 같은 두 층 구조다. `:root`의 `--r-*`를 `@theme`의 `--radius-*`가 참조하므로 유틸리티(`rounded-md`)와 컴포넌트 레이어(`var(--r-md)`)가 같은 값을 쓴다. **컴포넌트 레이어에서 `--radius-*`를 쓰면 안 된다** — §2.6의 이유 그대로다.

`rounded-xs`/`-sm`/`-md`/`-lg`/`-pill`만 쓴다. **접미사 없는 `rounded`는 쓰지 않는다** (덮이지 않는 기본값이라 스케일 밖으로 나간다).

### §2.6 globals.css 구조 🟡

```css
@import "tailwindcss";

/* 1. 원색 — 라이트/다크가 여기서 갈린다 */
:root {
  --paper: #f3f2f2;  --ink: #201e1d;  --surface: #eae9e9;
  --accent: #0088b0; --accent-ink: #006786; --accent-2: #d6006c;
  /* 램프 27개는 원본 styles.css에서 그대로 */
}
@media (prefers-color-scheme: dark) {
  :root {
    --paper: #201e1d;  --ink: #f3f2f2;  --surface: #2d2b2b;
    --accent: #99e0ff; --accent-ink: #99e0ff; --accent-2: #ffc0d0;
  }
}

/* 2. @theme inline — 값이 아니라 var()를 참조해야 다크가 런타임에 뒤집힌다 */
@theme inline {
  --color-bg: var(--paper);
  --color-text: var(--ink);
  /* … */
  --spacing: 5px;
  --radius-sm: 1px; --radius-md: 2px; --radius-lg: 4px;
  --font-heading: var(--sans);  /* :root의 --sans를 참조한다 */
}

/* 3. 컴포넌트 레이어 — §3 */
@layer components { /* .btn .tag .card … */ }
```

**`@theme inline`이어야 한다.** `@theme`은 값을 복사해 넣으므로 미디어 쿼리로 뒤집어도 유틸리티가 따라오지 않는다.

> ⚠️ **손으로 쓰는 CSS는 `--color-*`·`--text-*`를 쓰면 안 된다.** Tailwind는 유틸리티가 실제로 쓰지 않는 테마 변수를 `:root`에 내보내지 않는다 — 브라우저에서 확인한 결과 `--color-muted`와 `--text-body`는 **빈 문자열**이었다. 컴포넌트 레이어(§3)는 `--paper`·`--ink`·`--accent-ink`·`--muted`·`--bs-*`처럼 우리가 `:root`에 직접 선언한 이름만 쓴다. 이것이 토큰을 두 층으로 나눈 실질적인 이유다.

여백도 한 곳에서 나온다. `:root`의 `--space-unit: 5px`를 `@theme`의 `--spacing`이 참조하므로, 유틸리티(`p-3`)와 컴포넌트 레이어(`calc(var(--space-unit) * 3)`)가 같은 값을 쓴다.

**컴포넌트에 `dark:`를 쓰지 않는다.** 다크 대응은 토큰이 한다. 지금 코드에 깔린 `dark:` 변형은 전부 지운다 — 토큰이 뒤집히므로 필요 없다. 구조 자체가 달라져야 하는 예외만 `dark:`를 남기고, 그때는 이 문서에 적는다.

## §3 컴포넌트 레이어 ✅

**클래스로 만드는 것은 세 개뿐이다** — 여러 화면에서 반복되고, 상태(hover/active/focus)를 함께 들고 다녀야 하는 것들.

| 클래스 | 변형 | 쓰는 곳 |
|---|---|---|
| `.btn` | `-primary` `-secondary` `-ghost` `-block` | 모든 버튼·버튼처럼 보이는 링크 |
| `.tag` | `-solid` `-accent` `-accent-2` `-neutral` `-outline` `-quiet` | 배지 전부 |
| `.card` | `-kicker` `-title` `-body` `-meta` / `.elev-sm` | 목록 카드, 판정 블록, 내 조건 카드 |
| `.tile` | `-media` `-badge` `-body` | 타일 보기의 카드 (§5.1). **`.card`와 나눈 이유는 그림 자리가 가장자리까지 닿아야 하기 때문이다** — `.card`는 안쪽 여백을 갖고 있어 붙일 수 없다 |
| `.tag-btn` | `.tag`에 얹는 수식자 | 태그를 **컨트롤로** 쓸 때 (분야 칩). 손이 닿아야 하므로 13px·`6px 12px`로 키운다 — 표시용 3px 패딩은 24.8px라 누를 곳이 못 된다 |
| `.input` | — | 텍스트 입력·셀렉트 |

그 외(레이아웃·간격·1회성 스타일)는 전부 Tailwind 유틸리티다.

입력칸(`.input`)·라디오·세그먼트는 원본 `styles.css`의 정의를 그대로 옮기되, **쓰는 단계에서 만든다** — 목록의 검색창은 §9 4단계, 프로필 폼은 6단계다. 안 쓰는 CSS를 미리 깔지 않는다.

### 상태 ✅

원본 규칙 그대로. **브라우저 기본값을 남기지 않는다.**

| 상태 | 라이트 | 다크 |
|---|---|---|
| hover (채움) | `accent-800` | `accent-200` |
| active (채움) | `accent-900` | `accent-400` |
| hover (외곽선·고스트) | 잉크 7% 틴트 | 종이 10% 틴트 |
| focus-visible | `outline: 2px solid var(--color-accent); outline-offset: 2px` | 같음 |
| hover·active 적용 대상 | `:not(:disabled)`에만 — 비활성 버튼이 hover에 반응하면 눌리는 것처럼 읽힌다 | 같음 |
| disabled | `opacity: 0.45` | 같음 |
| `::selection` | accent 30% | 같음 |

## §4 이 프로젝트 고유의 결정

목업에 답이 없거나, 이 서비스에만 있는 것들이다.

### §4.1 5단계 점수 배지 ✅ (D5)

점수는 확인 항목 수에서 유도된다 ([score.ts](../src/lib/verdict/score.ts)). 원본 태그는 4종인데 5단계가 필요하다.

**색조로 5단계를 만들지 않는다. 잉크 농도로 만든다.** 신문 조판이 등급을 표현하는 방식이고(원본이 말하는 "black-and-white wedge"), 색맹 사용자에게도 순서가 남는다.

| 점수 | 표시 | 클래스 | 라이트 | 다크 | 잉크 | 대비(라이트/다크) |
|---|---|---|---|---|---|---|
| **5** 신청 가능 | `5 신청 가능` | `.tag-solid` | 채움 `accent-700` / 글자 종이색 | 채움 `accent-300` / 글자 먹색 | 가득 참 | 5.72 / 11.43 |
| **4** 확인 1개 | `4 확인 1개` | `.tag-accent` | `accent-100` / `accent-800` | `accent-900` / `accent-200` | 옅은 시안 | 9.10 / 11.44 |
| **3** 확인 N개 | `3 확인 N개` | `.tag-accent-2` | `accent-2-100` / `accent-2-800` | `accent-2-900` / `accent-2-200` | 옅은 마젠타 | 9.85 / 11.72 |
| **2** 조건 미기재 | `2 조건 미기재` | `.tag-neutral` | `neutral-200` / `neutral-800` | `neutral-800` / `neutral-200` | 중성 | 8.22 / 8.22 |
| **1** 아님 | `1 아님` | `.tag-quiet` | 테두리 `neutral-400` / 글자 `neutral-700` | 테두리 `neutral-700` / 글자 `neutral-400` | 비어 있음 | 5.83 / 8.27 |

- **채움은 5점 하나뿐이다.** 목록에서 "볼 게 있는지"가 한눈에 잡힌다.
- 3점에 마젠타를 쓰는 것은 "나쁨"이 아니라 **"여기를 봐야 함"**이다. 4점(시안)과 3점(마젠타)은 잉크가 다르지만 둘 다 옅다 — 농도가 서열이고 색은 성격이다.
- 한 배지 안에 잉크는 하나다 (원칙 3). `· 코드`/`· AI` 꼬리표는 같은 잉크의 70% 불투명도.
- **대비는 위 표의 실측값이다** (2026-08-06, 브라우저에서 계산). 가장 낮은 것이 5점 채움 5.72:1과
  1점 5.83:1 — 둘 다 AA(4.5:1)를 넘는다. 나머지는 8:1 이상이다.

### §4.2 출처 표시 ✅

`emerald`/`sky` 두 색으로 나누던 것을 **`.card-kicker` 한 형태로 통일한다** — 목업이 쓰는 방식이다.

```
온통청년          ← 12px, letter-spacing 0.08em, accent 잉크
서울 청년 월세 지원사업   ← card-title
```

**두 소스 모두 같은 잉크다.** 구분은 글자가 한다. 색을 하나 더 쓰면 판정 배지의 시안·마젠타와 경쟁한다.

배지가 아니게 됐으므로 컴포넌트 이름도 `SourceBadge` → **`SourceKicker`**로 바꿨다. 이름이 남아 있으면 다음 사람이 다시 알약 모양으로 칠한다.

### §4.3 인용 하이라이트 ✅

노란색을 쓰지 않는다. **`accent-100` 배경 / `accent-800` 글자** (다크: `accent-900` / `accent-200`) — 목업 스크립트가 쓰는 값 그대로다.

> ⚠️ [policies/[id]/page.tsx:215](../src/app/policies/[id]/page.tsx:215)의 안내문이 **"노란 표시가 판정 근거로 인용된 문장입니다"**라고 말한다. 색을 바꾸면 이 문장도 함께 고쳐야 한다 — `"표시된 문장이 판정 근거로 인용된 문장입니다"`.

`--color-process-yellow`는 인쇄 처리 전용이라 여기 쓸 수 없다 (§2.1).

### §4.4 그 밖의 배지 ✅

| 대상 | 클래스 |
|---|---|
| 분야 (주거·일자리…) | `.tag-neutral` |
| 조건 밖 | `.tag-outline` |
| 잠금 상태 등 운영 표시 | 범위 밖 (§5.4) |

### §4.5 흐림 처리 ✅

- 1점 카드: `opacity: 0.6` — 지금과 같다. **숨기지 않는다** (PRD §7.5).
- 필터 밖 항목(`전체 보기`): `opacity: 0.5` — 목업과 같다.

### §4.6 스켈레톤 ✅

판정 대기 중 배지 자리를 지키는 요소. **`.tag .tag-neutral`을 그대로 입고 폭만 `w-20`으로 고정한다** — 높이를 px로 박지 않는다.

> 배지 크기가 바뀌었을 때 자리 크기가 따라오지 않으면 이 컴포넌트의 존재 이유가 사라진다. 실제로 기존의 `h-[22px]`는 새 배지(24.8px)보다 **2.8px 짧아서**, 판정 결과가 도착하는 순간 카드가 튀고 있었다.

안에 `&nbsp;`가 들어간다. `.tag`가 `inline-flex`라 **보통 공백뿐인 텍스트는 익명 플렉스 항목으로 렌더되지 않아**(CSS Flexbox §4) 높이가 0으로 무너진다.

### §4.7 빈 상태 · 안내 ✅

박스를 두르지 않는다 (원칙 1). 가운데 정렬 대신 **왼쪽 정렬**, 위아래 `py-8` 여백.
제목은 `sub`(16px), 본문은 `small`(13px) `text-muted`. 목록의 `EmptyState`, 상세·프로필의 `Notice`가 같은 형태를 쓴다.

### §4.8 오류 잉크 ✅

**이 시스템에 빨강은 없다.** 팔레트는 시안·마젠타·중성뿐이고, 경고를 위해 네 번째 색을 들이면 스팟 컬러 규칙이 무너진다.

오류는 **마젠타의 깊은 단**을 쓴다 — `--danger`(유틸리티 `text-danger`).

| | 값 | 대비 |
|---|---|---|
| 라이트 | `accent-2-700` `#aa0b56` | 6.5:1 |
| 다크 | `accent-2-300` `#ffc0d0` | 10.8:1 |

본문 크기로 읽혀야 하므로 `--accent-2`(500 단계)를 그대로 쓰지 않는다 — §6.1 규칙 3과 같은 이유다.
성공·중립 메시지는 `text-muted`. **색만으로 성패를 말하지 않는다** — 문구가 먼저다.

## §5 화면별 적용

### §5.1 목록 `/` ✅

**목업의 화면 구성을 그대로 베끼지 않는다.** 목업은 판정이 3단계(해당·애매·아님)이고 범위 전환이 `.seg`인 시안이지만, 이 서비스는 5단계 점수에 필터가 URL 상태다. 아래가 실제 구조다.

- `border-b` 행 → **카드**, 구분선 없음.

#### 히어로 · 내 조건 카드 ✅ (D8)

첫 세 줄만 가운데다 — 제목 · 부제 · 건수 알약. **그 아래 모든 것은 왼쪽으로 돌아온다.** 첫 방문자가 읽어야 할 문장은 셋뿐이고, 그 셋은 훑는 대상이 아니라 읽는 대상이라 축을 세워도 손해가 없다. 목록까지 가운데로 끌고 가면 원칙 4가 실제로 무너진다.

건수는 `.tag-accent` 알약이다. 문장 안에 섞여 있던 숫자가 **덩어리로 잡힌다** — 레퍼런스가 "45,515개의 아이콘이 생성되었습니다" 자리에 쓰는 방식이다.

내 조건 카드(`max-w-read`)는 **무엇을 근거로 걸렀는지**를 실제 값으로 적는다. "조건을 한 번 넣어두면"이라는 약속을 `(1998년생) (서울특별시 관악구) (관심 2분야)`로 바꿔 보여주는 자리다. 세 상태를 갖는다.

| 프로필 | 카드 내용 |
|---|---|
| 없음 | "오른쪽 위 **내 조건 입력하기**로 생년과 사는 곳만 넣어도…" |
| 있고 비어 있음 | "비어 있습니다. 생년이나 사는 곳을 채우면…" (ARCHITECTURE §7의 그 상태다) |
| 있음 | 조건 칩 `.tag-neutral` |

> **판정 버튼은 이 카드에 없다.** 레퍼런스는 히어로의 입력 상자가 곧 주 동작이지만, 여기서는 버튼과 카드가 판정 상태를 공유해야 해서 `PolicyList` 안에 있어야 한다(ARCHITECTURE §6.1). 조건을 넣는 문도 마스트헤드 하나뿐이다 — 카드에 같은 링크를 또 두면 기능이 겹친다.

#### 보기 전환 ✅

`공고 둘러보기` 제목 오른쪽에 아이콘 두 개. **타일이 기본이고 `?view=list`로 목록이 된다.**

- 상태는 URL이다 — 필터와 같은 이유다(직접 접속·뒤로가기·공유가 그냥 되고, 첫 화면은 서버가 고른 보기로 그려져 깜빡이지 않는다). **기본값은 URL에 적지 않는다** — `/`와 `/?view=tile`이 같은 화면임이 주소에서 보여야 한다.
- ⚠️ **주소는 바꾸지만 서버는 부르지 않는다.** `<Link>`로 두면 URL이 바뀌므로 `force-dynamic` 페이지가 통째로 다시 렌더되고 프로필·목록·건수·판정·갱신시각 쿼리가 전부 다시 돈다 — **돌아오는 데이터는 방금 그린 것과 같다.** 실측 230~420ms(`application-code`)가 표시 방식을 바꾸는 데 들어가고 있었고, 프리페치까지 얹혀 마우스만 올려도 서버 렌더가 한 번 더 돌았다. 네이티브 `window.history.pushState`로 주소만 갈아끼우고 `useSearchParams()`가 다시 읽게 한다 — 클릭당 네트워크 요청 0건이다. 곁따라 오는 이득: `PolicyList`가 다시 마운트되지 않으므로 **판정 결과가 보기를 바꿔도 살아남는다.**
- `<button>`이 아니라 `<a href>`다. 주소를 복사하고 새 탭으로 열 수 있어야 하므로, 수식 키가 눌린 클릭은 브라우저에 그대로 넘긴다.
- 링크라 `aria-pressed`를 쓸 수 없다. 지금 보고 있는 쪽을 `aria-current="true"`가 말한다.
- 켜진 쪽만 채움(`accent-ink`), 꺼진 쪽은 `text-muted`. 40×40px. **`title`을 붙인다** — 아이콘만 있어서 마우스 사용자에게도 이름이 필요하고 `aria-label`은 툴팁을 띄우지 않는다.
- hover 틴트는 잉크 **10%**로, §3 표의 7%보다 진하다. 아이콘만 있는 40px 버튼에서 7%는 눌리는지 알 수 없다.

**두 보기는 정보량이 다르다.** 타일은 배지 · 분야 · 출처 · 제목 · 기관 · **판정 이유 두 줄**까지고, 인용문 · 확인 항목 목록 · 블로커는 목록 보기에만 있다. 3열에 들어가려면 카드가 짧아야 하고, 짧은 카드에 그것들을 우겨넣으면 어느 것도 안 읽힌다. 배지만 남기지 않은 이유도 같다 — 이유가 없으면 목록이 점수표가 된다.

#### 타일의 그림 자리 ✅

레퍼런스는 아이콘 사이트라 카드가 이미지로 시작하는데 **공고에는 이미지가 없다.** 카드 하나를 대표하는 성질 중 그림으로 만들 수 있는 것은 분야뿐이라, 16:9 자리에 분야 선화 9종을 세웠다 ([CategoryIcon.tsx](../src/components/CategoryIcon.tsx)).

- 워시는 `--tint-accent-bg`가 아니라 **accent 8%**다. 그 토큰은 4점 배지의 채움이라(§4.1) 모든 타일이 그 색이면 배지가 묻힌다. 잉크는 하나이고 농도만 다르다 (원칙 3).
- 선화는 `currentColor`로 그린다 — 색은 `.tile-media`가 정한다. 선 굵기 1.6 · 둥근 끝 · 24 격자로, 로고와 보기 전환 아이콘이 쓰는 값과 같다.
- **그림만으로는 뜻이 안 전해진다.** 선화는 `aria-hidden`이고, 분야 이름을 본문 첫 줄에 출처와 나란히 태그로 적는다 (§6.2와 같은 판단).
- 배지는 그림 위 오른쪽 위다 — 목록 카드·상세와 같은 자리라 화면이 이어진다.

**대가는 높이다.** 타일이 220 → 366px가 되어 한 화면에 보이는 공고 수가 줄어든다. 그림이 정보를 늘려주지는 않는다는 것을 알고 택한 것이고(§7), 전부 펼쳐 보려면 목록으로 전환한다.

#### 마스트헤드 ✅

브랜드 줄이 페이지 안의 첫 블록에서 **위에 고정된 막대**로 나왔다. 브랜드는 왼쪽, 지금 할 일은 오른쪽이다.

- **괘선은 원칙 1의 예외가 아니다.** `divider`는 "꼭 필요한 한 줄"에 쓰라고 되어 있고(§2.1),
  스크롤하는 내용 위에 떠 있는 막대는 그 경계가 없으면 어디까지가 막대인지 읽히지 않는다.
  신문 제호 아래의 괘선과 같은 자리다.
- 배경은 `bg-bg/85` + `backdrop-blur-sm`. 불투명하게 덮지 않는 이유는 아래로 흐르는 카드가
  막대에 가려 잘리는 게 아니라 **지나가는 것으로** 보여야 하기 때문이다.
- 안쪽은 `max-w-page`로 본문과 같은 폭에 정렬한다 — 막대만 전체 폭이다.

#### 화면에 채움 버튼은 하나 ✅

조건 유무로 **어느 것이 채움인지가 갈린다.** 둘이 동시에 채움인 상태는 없다.

| 조건 | 마스트헤드 | 목록 |
|---|---|---|
| 없음 | `내 조건 입력하기` **`.btn-primary`** | 판정 버튼 없음 — `small·muted` 안내문 (F-15) |
| 있음 | `내 조건 수정` `.btn-secondary` | `이 페이지 N건 판정하기` **`.btn-primary`** |

> **`/profile`로 가는 링크는 화면에 하나뿐이다.** 전에는 헤더의 `내 조건 입력하기`와 목록의
> `내 조건 입력하고 판정받기`가 **같은 곳으로 가는 버튼 두 개**였다. 목록 쪽을 글로 바꿨다 —
> 마스트헤드는 어느 상태에서도 화면에 있으므로, 카드가 0건이라 목록이 안 그려지는 상태에서도
> 조건을 넣을 문이 남는다.

마스트헤드는 **목록 화면에만 있다.** 상세·프로필은 `← 목록으로`로 돌아가는 읽기 화면이고(§5.2·§5.3),
거기에 막대를 얹으면 돌아가는 길이 둘로 늘어난다.

### §5.2 상세 `/policies/[id]` ✅

`max-w-read`(680px). 위에서부터: `← 목록으로`(`.btn-ghost px-0`) → 제목 + 점수 배지 → 메타 한 줄 → 분야 태그 → **판정 블록만 `.card`** → 원문(박스 없이) → 신청 안내(박스 없이).

- **상자를 두른 블록은 판정 근거 하나뿐이다.** `rounded border` 박스 네 개 중 셋을 없앴고, 그 자리는 `text-sub` 제목과 여백이 나눈다 (원칙 1). 카드 안의 '확인이 필요한 것' 패널만 종이색으로 한 겹 더 들어간다.
- **점수 배지를 제목 옆으로 올렸다.** 목록에서 본 배지가 상세에서도 같은 자리(오른쪽 위)에 있어야 화면이 이어진다. 전에는 판정 섹션 안에 있었다.
- 출처·기관은 알약을 벗고 메타 한 줄이 된다 — 목록의 키커와 역할이 같고, 여기서는 굳이 잉크를 쓸 자리가 아니다.
- 원문은 `whitespace-pre-wrap`을 유지하고 행간만 1.7로 (14px / 23.8px).
- `원문 보기 ↗`·`☆ 스크랩` = `.btn-secondary`, `★ 스크랩 해제` = `.btn-ghost`. **이 화면에는 채움 버튼이 없다** — 읽는 화면이고, 해제는 되돌리는 동작이지 권하는 동작이 아니다.

### §5.3 프로필 `/profile` ✅

`max-w-read`(680px). 각 `fieldset`은 `legend`(`sub` 16px) + 여백으로 구분한다. **선이 남는 자리는 저장 버튼 위 한 줄뿐** — 입력이 끝나고 동작이 시작되는 경계다.

라디오·체크박스는 **`.chip`**으로 통일했다 (§8-3 결정). 마크업은 `<label class="tag tag-btn tag-outline chip">`가 네이티브 입력을 감싼 형태다.

> **왜 목록의 분야 칩과 같은 모습인가.** 같은 것(분야)을 고르는 컨트롤이 화면마다 다르게 생기면 사용자는 다른 기능으로 읽는다.
>
> **왜 `<button>`이 아닌가.** 목록 쪽은 `<button>` + React 상태지만, 프로필 폼은 **비제어 입력**이어야 한다 — 저장이 실패해 폼이 다시 그려져도 고른 값이 남아야 하기 때문이다([ProfileForm.tsx](../src/components/ProfileForm.tsx)의 설계). 그래서 켜짐/꺼짐을 React가 아니라 `:has(input:checked)`로 CSS가 판단한다.
>
> 입력은 `position:absolute; width:0; height:0; opacity:0`으로 숨기되 **포커스는 살아 있다.** 숨겼으므로 포커스 링은 라벨이 대신 받는다(`.chip:has(input:focus-visible)`) — 안 그러면 키보드 사용자가 자기 위치를 알 수 없다.
>
> 켜졌을 때 `::before`로 붙는 ✓는 장식이 아니라 **색을 못 보는 사용자를 위한 두 번째 단서**다 (§6.2).

- 생년 입력칸은 `w-24`(120px). `--spacing` 확대로 160px까지 벌어졌던 것을 되돌렸다 (§8-2).
- 셀렉트는 `.input w-auto`.
- 저장 버튼은 `.btn-primary` — 이 화면의 유일한 채움 버튼이다.
- 오류 메시지는 `text-danger` (§4.8).

### §5.4 관리자 `/admin` — 범위 밖 ✅

토큰만 상속한다 (색·서체·여백이 자동으로 따라온다). **레이아웃·표·막대 그래프는 건드리지 않는다.**
단, `gray-*`·`amber-*`·`red-*`·`green-*` 하드코딩은 남으므로 종이 배경과 어긋나 보일 수 있다 — 의도된 미완이다.

## §6 접근성 기준 ✅

### §6.1 대비

**측정값을 근거로 정한 규칙이다.**

| 조합 | 대비 | 판정 |
|---|---|---|
| `accent`(#0088b0) 채움 + 종이 글자 | 3.7:1 | ❌ 작은 글자 불가 → D4 |
| `accent-700`(#006786) 채움 + 종이 글자 | 5.7:1 | ✅ |
| `text-muted`(잉크 70%) on 종이 | 5.81:1 | ✅ |
| `text-muted`(잉크 70%) on 카드 `surface` | 6.00:1 | ✅ 카드가 밝아지며 5.59 → 6.00으로 올랐다 (D7) |
| `.tag-quiet` 글자(neutral-700) on 카드 | 6.26:1 | ✅ 1점 태그가 카드 위에 놓이는 경우 |
| 카드 `surface` vs 종이 `bg` | 1.07:1 | 층 구분용. 경계는 `divider` 한 줄이 만든다 |
| `text-faint`(잉크 55%) on 종이 | 3.6:1 | ❌ 본문 불가 — 장식용만 |
| 점수 배지 5단계 | 5.72 ~ 9.85:1 | ✅ §4.1 표 참조 |

규칙:
1. **채움 배경 위 작은 글자는 `accent-ink`(700)를 쓴다.** `accent`는 링크·아이콘·테두리·큰 글자용.
2. **읽어야 하는 보조 텍스트는 `text-muted`(70%)까지만.** 원본의 `.card-meta`(50%)·`figcaption`(55%)은 이 프로젝트에서 70%로 올린다.
3. 본문 크기의 accent 텍스트는 라이트에서 `accent-700`, 다크에서 `accent-300`.

### §6.2 색에만 기대지 않는다

점수 배지는 **숫자 + 말**을 함께 적는다 (`5 신청 가능`). 이미 그렇게 되어 있고 ([badges.tsx:47](../src/components/badges.tsx:47)), 잉크 농도 계단(§4.1)이 색과 독립된 두 번째 단서다.

### §6.3 포커스

`:focus-visible { outline: 2px solid var(--color-accent); outline-offset: 2px }`.
**기본 파란 링을 남기지 않는다.** 세그먼트 컨트롤 안쪽 요소만 `outline-offset: -2px`.
