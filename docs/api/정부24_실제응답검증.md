# 정부24 공공서비스 정보 API — 실제 응답 검증 기록

- 검증일: 2026-08-05 (작업 0-B)
- 대상: [정부24_공공서비스정보API.md](정부24_공공서비스정보API.md) 명세가 실제 응답과 일치하는지
- 결론: **명세대로 동작한다. 벌크 조회가 되고, 텍스트 채움률이 온통청년보다 훨씬 좋다**

```
GET https://api.odcloud.kr/api/gov24/v3/{serviceList|supportConditions}
Header: Authorization: Infuser <KEY>
```

인증키에 `+`와 `==`가 포함되어 있어 **쿼리스트링(`serviceKey`)이 아니라 `Authorization` 헤더로 보낸다.** 발급값이 `Infuser `로 시작하므로 그 문자열 전체가 헤더 값이다.

---

## 1. 규모 — 두 엔드포인트가 1:1로 맞는다

| 엔드포인트 | totalCount |
|---|---|
| `serviceList` | **10,964** |
| `supportConditions` | **10,964** |

건수가 정확히 같다. `서비스ID`로 조인하면 누락 없이 붙는다 (표본 2,000건 조인 실패 0건).

## 2. ★ `supportConditions`를 서비스ID 없이 벌크 페이징할 수 있다

작업 0-B의 최우선 확인 항목이었다. **가능하다.**

```
GET /supportConditions?page=1&perPage=100    → 100건 반환, totalCount=10964
```

`cond[서비스ID::EQ]` 없이 호출하면 전량이 페이징된다. 그래서 **서비스마다 1회씩 호출(=10,964회)할 필요가 없고**, `perPage=100`으로 110페이지씩 두 엔드포인트를 각각 훑어 메모리에서 Map 조인하면 된다.

→ 검증 전 폴백으로 준비했던 "`cond[서비스분야::LIKE]`로 좁혀 수집"은 **필요 없다.** 전량을 그대로 받는다 ([ARCHITECTURE §4.2](../ARCHITECTURE.md)).

## 4. 자격 코드 — 명세의 `JA****`가 실제로 온다

`supportConditions` 레코드는 **50개 필드**이고 그중 대부분이 `JA****` 코드다. 값은 `"Y"` 또는 `None`.

**표본 500건 채움률**

| 그룹 | 채움률 |
|---|---|
| 성별 `JA0101/0102` | 63.4% |
| 연령 `JA0110/0111` | 67.8% |
| 소득 `JA02xx` | 63.4% |
| 개인상황 `JA03xx` | 63.6% |
| 가구상황 `JA04xx` | 63.6% |
| 기관유형 `JA21xx/22xx` | 42.0% |
| 사업자 `JA11xx` | 6.2% |
| 업종 `JA12xx` | 5.4% |

### 4.1 ★ 값 해석 규칙 (명세에 없음 — 실측으로 확정)

실제 레코드 예:

```jsonc
{ "JA0101": "Y", "JA0102": "Y",              // 남녀 모두 Y
  "JA0110": 3, "JA0111": 5,
  "JA0201": "Y", ... "JA0205": "Y",          // 소득 5구간 전부 Y
  "JA0322": "Y",                             // 해당사항없음
  "JA0401": "Y", ... "JA0414": "Y" }         // 가구 전부 Y
```

**한 그룹의 값이 전부 `Y`인 것은 "제한 없음"을 뜻한다.** 그래서 게이트 규칙은 셋으로 나뉜다.

| 그룹의 상태 | 의미 | 게이트 |
|---|---|---|
| 전부 `None` | 조건 정보 없음 | **통과** |
| 전부 `Y` | 제한 없음 | **통과** |
| 일부만 `Y` | 그 항목만 대상 | 내 코드가 `Y`일 때만 통과 |

이 규칙을 안 지키면 **"전부 Y"인 정책을 교집합 검사로 떨어뜨려서 대량 오판**이 난다.

### 4.2 연령 상한 `120`은 "상한 없음"이다

```
19 ~ 120세   60건       18 ~ 64세   46건
18 ~ 120세   55건       18 ~ 65세   13건
60 ~ 120세    9건       13 ~ 18세    3건
```

`JA0111 = 120`이 가장 흔하다. 실제 나이 상한이 아니라 무제한 표시이므로, 게이트에서 `120`은 상한 없음으로 읽는다.

## 5. ★ 지역 판별이 가능하다 — 그것도 시군구 단위로

명세에 지역 코드 필드가 없어 못 할 것으로 봤으나(PRD R9), `소관기관명`이 **`"서울특별시 동대문구"` 형태**로 온다.

| 항목 | 값 |
|---|---|
| 시도명으로 시작하는 비율 | **99.1%** (비중앙 기관 1,314건 중 1,302건) |
| 판별 실패 | `한국주택금융공사`, `재단법인영등포구미래교육재단`, `(재)달성교육재단` — 공공기관·재단 3종 |
| 소관기관유형 | 시군구 65.1% / 중앙행정기관 34.3% / 지방출자·출연기관 0.6% |

`소관기관유형 = 중앙행정기관`이면 전국 서비스다.

### 5.1 지역별 실제 건수 (서버 `matchCount`, 추정 아님)

```
cond[소관기관명::LIKE]=<시도명>
```

| 지역 | 건수 |
|---|---|
| 전체 | 10,964 |
| **중앙행정기관 (전국)** | **1,053** |
| **경기도** | **1,155** |
| **서울특별시** | **968** |
| **인천광역시** | **298** |
| (참고) 부산광역시 | 336 |

**수도권 거주자에게 유효한 것 = 수도권 2,421 + 전국 1,053 = 3,474건 (31.7%).** 지역 필터가 68.3%를 걷어낸다.

> ⚠️ 페이지 1~20 표본으로 추정했을 때는 81.3%가 남는다고 나왔는데 **틀렸다.** 표본이 서울 구청 정책에 편중돼 있었고 경기도가 0건이었다. 비율은 표본이 아니라 `matchCount`로 확인해야 한다.

### 5.2 시군구 이름을 데이터에서 도출할 수 있다

`소관기관명`에서 시도명을 떼면 시군구 이름이 나온다. 표본 2,000건 기준:

- **서울특별시 25개** — 강남·강동·강북·강서·관악·광진·구로·금천·노원·도봉·동대문·동작·마포·서대문·서초·성동·성북·송파·양천·영등포·용산·은평·종로·중·중랑
- **인천광역시 7개** — 계양·남동·미추홀·부평·연수·**영종·제물포**
- **경기도 0개** ← 표본 편중. 전량 수집 후 다시 도출해야 한다

**인천에 `영종구`·`제물포구`가 있다.** 행정구역이 재편된 상태의 데이터이므로, **외부 코드표나 기억에 의존한 시군구 목록을 하드코딩하면 안 된다.** 반드시 수집 데이터에서 도출한다.

## 8. 응답 껍데기

```jsonc
{ "page":1, "perPage":100, "totalCount":10964,
  "currentCount":100, "matchCount":10964, "data":[ ... ] }
```

- `matchCount` = 조건에 맞는 전체 수. **건수만 알고 싶으면 `perPage=1`로 부르고 이 값만 읽으면 된다**
- HTTP 상태로 성공/실패가 오고, 401은 인증 실패

## 9. 남은 미확정

- **경기도 시군구 목록** — 표본에 없었다. 전량 수집 후 도출
- `serviceDetail`(구비서류 등)은 호출해보지 않았다. **표시 전용 필드라 판정에 영향 없음.** 필요해지면 그때 붙인다
- `JA12xx`(업종)·`JA11xx`(사업자) 채움률이 6% 안팎이라, 창업 관련 판정은 코드보다 `지원대상` 텍스트에 의존하게 된다
