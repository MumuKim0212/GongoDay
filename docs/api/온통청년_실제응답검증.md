- 대상: [온통청년_청년정책API.md](온통청년_청년정책API.md)의 명세가 실제 응답과 일치하는지
- 결론: **명세가 실제 응답보다 크게 빈약하다.** 명세만 보고 설계하면 안 된다

## 2. 명세에 없었지만 실제로 오는 필드

명세의 출력 표에는 `plcyNo`, `plcyNm`, `plcyKywdNm`, `plcyExplnCn`, `lclsfNm`, `aplyYmd`, `frstRegDt`, `lastMdfcnDt`, `sBizCd` 정도만 있었다. 실제로는 아래가 모두 온다.

### 자격요건 (설계에 결정적)

| 필드 | 예시 | 용도 |
|---|---|---|

| **`addAplyQlfcCndCn`** | `"19~39세 청년, 청년 모임 및 동아리"` | **AI 판정의 주 입력** |
| `ptcpPrpTrgtCn` | `""` | AI 판정 보조 |
| `earnCndSeCd`, `earnMinAmt`, `earnMaxAmt`, `earnEtcCn` | `"0043001"`, `"0"`, `"0"`, `""` | 코드 의미 불명 → 보관만 |

### 본문 텍스트

`plcySprtCn`(지원내용), `etcMttrCn`(기타사항), `srngMthdCn`(심사방법), `plcyAplyMthdCn`(신청방법), `sbmsnDcmntCn`(제출서류)

### 기관·분류·링크

`mclsfNm`(중분류 — 명세 누락), `sprvsnInstCdNm`(주관기관), `rgtrHghrkInstCdNm`(등록 상위기관), `aplyUrlAddr`, `refUrlAddr1`, `refUrlAddr2`, `sprtSclCnt`, `inqCnt`

### 기간

`aplyPrdSeCd`, `bizPrdSeCd`, `bizPrdBgngYmd`, `bizPrdEndYmd`, `bizPrdEtcCn`

## 3. 데이터 품질 문제 (수집 코드가 반드시 처리해야 함)

| 문제 | 실제 값 |
|---|---|
| **공백만 있는 문자열** | `bizPrdBgngYmd: "        "` (공백 8개), `operInstCd: "       "` (7개) |
| **`aplyYmd`가 자주 빈 값** | 3건 중 2건이 `""`. 값이 있으면 `"20260727 ~ 20260814"` 형식 |
| **개행 혼재** | 같은 응답 안에 `\n`과 `\r\n` |
| **크롤링 잔여물** | `plcySprtCn` 끝에 `"[출처] … \|작성자 광산 청년온가"` |
| 숫자가 문자열로 옴 | `sprtTrgtMinAge: "19"` |

→ 대응 규칙은 [ARCHITECTURE.md §2.1.4](../ARCHITECTURE.md)

## 4. `sprtTrgtAgeLmtYn`을 쓰지 않는 이유

첫 번째 레코드는 이 값이 `"N"`인데, 같은 레코드의 `etcMttrCn`에는 `"□ 대 상 : 19세~39세 청년"`이 명시되어 있고 `sprtTrgtMinAge`/`MaxAge`도 `19`/`39`다. 세 번째 레코드는 `"Y"`이면서 역시 19~39세다.

**플래그 값이 원문과 일치하지 않는다.** 의미를 확정할 수 없으므로 판정에 쓰지 않고, `sprtTrgtMinAge`/`sprtTrgtMaxAge`만 사용한다.

## 5. 지역 코드 매핑을 데이터에서 도출할 수 있다

| `zipCd` | `rgtrHghrkInstCdNm` |
|---|---|
| `11380` | 서울특별시 |
| `12190` | 전남광주통합특별시 |
| `12110,12130,…` | 전남광주통합특별시 |

앞 2자리와 상위기관명이 대응한다. 코드표를 외부에서 구하지 않고 수집 데이터에서 뽑아낼 수 있다 → [ARCHITECTURE.md §2.6](../ARCHITECTURE.md)

## 6. 남은 미확정

**코드정의서를 확보하지 못했다.** `earnCndSeCd`, `jobCd`, `schoolCd`, `plcyMajorCd`, `mrgSttsCd`, `aplyPrdSeCd`, `plcyPvsnMthdCd`, `plcyAprvSttsCd`의 의미를 모른다.

3건 표본에서 모두 같은 값이라 "제한 없음"일 가능성이 있으나 **추측하지 않는다.** `eligibility_codes` jsonb에 보관만 하고 판정에 쓰지 않는다. 확보하면 코드 게이트 범위를 넓힐 수 있으나 나이·지역만으로도 게이트가 성립하므로 필수는 아니다.

# 7. 전량(2,698건) 수집 후 재검증 — 2026-08-05

3건 표본으로 세운 가정 중 **둘이 깨졌다.** 27페이지 전량을 받아 다시 셌다.

## 7.1 ★ "빈 zipCd = 전국"이 아니다 — 전국은 256개 코드를 전부 나열한다

| 항목 | 실측 |
|---|---|
| `zipCd`가 빈 정책 | **0건 (0.0%)** |
| 단일 시도 정책 | 2,275건 (84.3%) |
| 15개 시도 이상에 걸친 정책 | **416건 (15.4%)** — 대부분 코드 256개를 전부 나열 |
| 전국 시군구 코드 distinct | 261개 |

즉 **전국 정책은 `zipCd`를 비우는 게 아니라 전 시군구를 나열한다.** 예: `햇살론유스`(금융위), `청년일자리도약장려금`(고용노동부) — 전부 256개.

→ ARCHITECTURE의 "`region_codes`가 빈 배열이면 전국" 규칙은 **이 데이터에서 한 번도 발동하지 않는다.** 전국 판정은 "시도 prefix가 15개 이상"으로 해야 한다.

## 7.2 ★ 지역 매핑은 `rgtrHghrkInstCdNm`으로 못 뽑는다

전량으로 뽑으니 prefix마다 상위기관명이 **52~53종씩** 섞여 나왔다. 원인은 §7.1의 전국 정책(416건)이 자기 기관명을 모든 prefix에 뿌리기 때문이다.

**단일 시도 정책(84.3%)만 골라내면 깨끗하게 나온다.**

| prefix | 지역 | prefix | 지역 |
|---|---|---|---|
| 11 | 서울특별시 | 41 | 경기도 |
| 12 | **전남광주통합특별시** | 43 | 충청북도 |
| 26 | 부산광역시 | 44 | 충청남도 |
| 27 | 대구광역시 | 47 | 경상북도 |
| 28 | 인천광역시 | 48 | 경상남도 |
| 30 | 대전광역시 | 50 | 제주특별자치도 |
| 31 | 울산광역시 | 51 | 강원특별자치도 |

**16개.** 전남(46)이 없고 12가 광주·전남 통합 코드다. 강원 51, 전북 52는 특별자치도 코드.

**이 코드 체계는 표준 법정동코드와 다르다.** 외부 코드표로 맞출 수 없고, 데이터에서 뽑는 것이 유일한 방법이었다.
